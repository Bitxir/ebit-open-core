# Contributing

Thanks for helping build EBiT Open Core.

1. Open an issue describing the change before large pull requests.
2. Keep changes small and focused; one feature or fix per pull request.
3. Add or update tests for any rule you change (`bun run test`).
4. Update the matching page in `docs/` — documentation ships with the code.
5. Never commit secrets or real personal data. Sample data must be synthetic or openly licensed with attribution.
6. Do not claim support for a format, standard or partner that is not implemented and tested.

## Adding an adapter

See [Adapters](/docs/adapters). An adapter pull request needs: the module, registry entry, a sample file, and a test.
